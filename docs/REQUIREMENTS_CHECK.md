# Requirements check

Every written requirement was checked against the code and by running it. Sources of requirements:

* **Scenario 01 / 02 / 03** — the real Drive documents, read from `evaluation-projects/docchange/docchange/drive_snapshot/` (`01_Website_Requirements.md`, `02_Weather_Requirements_v1.md`, `03_RAG_Requirements_v1.md`). The `…_v2_MOCK` files in that folder are invented test revisions and were **not** used as requirements.
* **Project context rules** — `05_Project_Context.md` (same folder).
* **Uploaded projects** (inventory, appointment, expense, support, document change monitor) — no requirement document was supplied. Their README feature lists were checked instead, and are labelled as the projects' own scope.

Statuses: **Met** = implemented and shown by a test or a run today · **Not met** = cannot be satisfied from this environment (reason given) · **Unverified** = implemented but not exercised against the real external service.

## Defects found and fixed during this check

1. **Prompt C test failed on Windows** (`test_higher_version_wins_even_without_superseded_wording`): the test wrote a file containing "—" using the platform default encoding while the app reads UTF-8. Fixed by writing the test files as UTF-8. The fix is in the Prompt C repository's working tree (it is a nested git repository and was not committed there).
2. **Root README status table was out of date**: it omitted five projects and still said Docker had not been run. Updated.
3. **Inventory README** said 23 tests; there are now 24 (a favicon test was added). Updated in its working tree.
4. **Earlier in this work:** the inventory server returned 404 for `/favicon.ico` (fixed); the appointment and expense apps needed `tzdata` on Windows (added to their requirements).
