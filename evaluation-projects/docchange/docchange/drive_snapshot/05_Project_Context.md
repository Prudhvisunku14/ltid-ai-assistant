# Project Context & Development Standards

Fictional internal working practices

# Context

Northstar Services and Northstar Studio are fictional clients used in this training exercise.

For each scenario the GitHub starter repository is an incomplete baseline; the Drive specification is the source of truth for requirements.

# Workflow requirements

Propose a short plan before non-trivial code changes and link it to the relevant documented requirement.

Use a separate branch; run automated tests before preparing a pull request.

Show what changed, what was tested, what remains unverified, and any assumptions.

Do not automatically merge or deploy to production.

# Security and privacy

Never paste an API key into a repository or chat log.

Do not access folders, repositories or endpoints outside the granted scope.

All generated code must run in an isolated workspace with human-approved permissions.
